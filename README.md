# Платформа совместных покупок (Joint Purchases)

## Назначение
Консольное приложение для организации совместных покупок. Пользователь
присоединяется к совместной покупке товара, чтобы приобрести его оптом по
более выгодной цене. Приложение ведёт учёт покупок, пользователей и участий,
отслеживает набор участников и сохраняет данные между запусками.

В ПР3 проект переведён с функциональной модели на **объектно-ориентированную**:
основные сущности предметной области представлены классами, а данные — их
объектами.

## Целевая аудитория
- Частные покупатели, желающие покупать товары оптом по сниженной цене.
- Организаторы совместных покупок, координирующие группы участников.
- Небольшие сообщества (коллеги, соседи, тематические группы).

## Предметная область
Совместная покупка — форма коллективного приобретения товара, при которой
несколько участников объединяют заказы ради оптовой цены. Пользователь
присоединяется к покупке (создаёт участие). Покупка состоится, когда наберётся
минимальное число участников и не будет превышено максимальное. Отменённое
участие освобождает место и не учитывается при наборе.

## Основные сущности (классы)

### Purchase — совместная покупка
- Атрибуты: `id`, `product`, `price`, `min_participants`, `max_participants`.
- Методы: `has_free_slots()` — есть ли свободные места; `is_reached()` —
  набран ли минимум; `participant_cost()` — стоимость участия с комиссией;
  `validate_price()` (`@staticmethod`); `__str__()`.

### User — пользователь
- Атрибуты: `id`, `name`, `email`.
- Методы: `from_data()` (`@classmethod`) — создание из словаря JSON;
  `__str__()`.

### Participation — участие в покупке
- Атрибуты: `id`, `purchase` (объект `Purchase`), `user` (объект `User`),
  `is_cancelled`.
- Методы: `cancel()` — отмена участия (меняет состояние, не удаляя объект);
  `__str__()`.

## Взаимодействие объектов
`Participation` связывает объекты `User` и `Purchase` (композиция): хранит
ссылки на них, а не идентификаторы. Благодаря этому данные связанных объектов
доступны напрямую: `participation.user.name`, `participation.purchase.product`.

```
User ──создаёт──> Participation ──относится к──> Purchase
```

## Основные операции
- Работа с покупками: просмотр, поиск по названию, отбор по цене, сортировка.
- Работа с пользователями: просмотр, поиск, создание.
- Работа с участиями: создание (с проверкой свободных мест), отмена, просмотр.

## Хранение данных
Данные хранятся в JSON-файлах каталога `data/`. При загрузке данные
преобразуются в объекты `Purchase`, `User` и `Participation`, при сохранении —
обратно в структуры JSON. В `participations.json` связи с покупкой и
пользователем хранятся через идентификаторы (`purchase_id`, `user_id`).
Чтение и запись выполняются через контекстный менеджер `with` с обработкой
исключений (отсутствие файла, некорректный JSON).
