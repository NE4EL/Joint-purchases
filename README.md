# Платформа совместных покупок (Joint Purchases)

Система совместных покупок на Python с веб-интерфейсом на Django.

## Назначение
Приложение для организации совместных покупок. Пользователь присоединяется к
совместной покупке товара, чтобы приобрести его оптом по более выгодной цене.
Приложение ведёт учёт покупок, пользователей и участий, отслеживает набор
участников и предоставляет доступ к информации через веб-интерфейс Django.

Проект развивается постепенно: консольная версия приложения (ПР1–ПР3)
дополнена веб-интерфейсом на Django (ПР5), который в ПР6 переведён на систему
шаблонов Django. В ПР7 проект получил слой реляционного хранения данных:
база данных SQLite, SQL-запросы и получение данных в Django-представлениях
средствами модуля `sqlite3`.

## Целевая аудитория
- Частные покупатели, желающие покупать товары оптом по сниженной цене.
- Организаторы совместных покупок, координирующие группы участников.
- Небольшие сообщества (коллеги, соседи, тематические группы).

## Предметная область
Совместная покупка — форма коллективного приобретения товара, при которой
несколько участников объединяют заказы ради оптовой цены. Пользователь
присоединяется к покупке (создаёт участие). Покупка состоится, когда наберётся
минимальное число участников и не будет превышено максимальное. Отменённое
участие освобождает место и не учитывается при наборе.

## Основные сущности (классы)

### Purchase — совместная покупка
- Атрибуты: `id`, `product`, `price`, `min_participants`, `max_participants`.
- Методы: `has_free_slots()`, `is_reached()`, `participant_cost()`,
  `validate_price()` (`@staticmethod`), `__str__()`.

### User — пользователь
- Атрибуты: `id`, `name`, `email`.
- Методы: `from_data()` (`@classmethod`), `__str__()`.

### Participation — участие в покупке
- Атрибуты: `id`, `purchase` (объект `Purchase`), `user` (объект `User`),
  `is_cancelled`.
- Методы: `cancel()`, `__str__()`.

Предметные сущности реализованы собственными Python-классами. На текущем этапе
данные хранятся в JSON-файлах; Django ORM и база данных пока не используются.

## Веб-интерфейс
Веб-часть приложения реализована на Django. Основные страницы:
- главная страница (`/`);
- список совместных покупок (`/purchases/`);
- информация об отдельной покупке (`/purchases/<id>/`);
- список участий (`/participations/`);
- информация об отдельном участии (`/participations/<id>/`);
- подбор покупок по бюджету (`/purchases/search/`);
- статистика участия по покупкам (`/participations/statistics/`).

Для формирования страниц используются Django-шаблоны. Генерация HTML
непосредственно в Python-коде веб-представлений не используется (функция
`page()` из ПР5 удалена). Представления подготавливают данные и передают их в
шаблоны через контекст.

## Django Template Language
Шаблоны используют возможности Django Template Language.

### Базовый шаблон
Общий шаблон страницы — `templates/base.html`. Он содержит общую HTML-структуру,
подключение стилей и JavaScript, навигацию и блоки для содержимого страниц.
Дочерние шаблоны используют наследование (`{% extends "base.html" %}`) и
переопределяют блоки `{% block title %}` и `{% block content %}`.

### Включаемые шаблоны
Повторяющиеся фрагменты вынесены в отдельные шаблоны и подключаются через
`{% include %}`:
- навигация — `templates/includes/navigation.html`;
- карточка покупки — `purchases/includes/purchase_card.html`;
- статус участия — `participations/includes/participation_status.html`.

### Контекст, циклы и условия
Представления передают данные в шаблоны через словарь контекста. В шаблонах
для формирования списков используются циклы `{% for %}` (с `{% empty %}` для
пустых коллекций), а для различных состояний — условия `{% if %}` (например,
`participation.is_cancelled`).

## Фильтры шаблонов
В шаблонах используются стандартные фильтры DTL: `{{ purchases|length }}` —
количество элементов, `{{ purchase.product|default:"Без названия" }}` — значение
по умолчанию. Фильтры используются только для представления данных и не
содержат бизнес-логику.

## URL-маршрутизация
Для страниц используются именованные маршруты Django с пространствами имён
(`app_name`): `homepage:index`, `purchases:list`, `purchases:detail`,
`participations:list`, `participations:detail`. Ссылки в шаблонах формируются
через `{% url %}`, а не жёстко заданными адресами.

## Статические файлы
Статические файлы проекта находятся в каталоге `homepage/static/homepage/`:
- `css/style.css` — собственные стили проекта;
- `js/main.js` — JavaScript (вывод текущего года в подвале);
- `img/logo.png` — логотип.

В шаблонах статика подключается через `{% load static %}` и `{% static %}`.

## База данных (SQLite)
Начиная с ПР7 проект использует реляционную базу данных SQLite
(`data/joint_purchases.sqlite`). Исходные JSON-файлы сохранены как первичные
данные и переносятся в базу скриптом импорта.

### Структура базы данных
Таблица `purchases` — совместные покупки:

| Поле | Тип | Назначение |
|------|-----|------------|
| `id` | INTEGER | идентификатор, первичный ключ |
| `product` | TEXT | название товара |
| `price` | REAL | цена |
| `min_participants` | INTEGER | минимум участников |
| `max_participants` | INTEGER | максимум участников |

Таблица `users` — пользователи:

| Поле | Тип | Назначение |
|------|-----|------------|
| `id` | INTEGER | идентификатор, первичный ключ |
| `name` | TEXT | имя пользователя |
| `email` | TEXT | электронная почта |

Таблица `participations` — участия в покупках:

| Поле | Тип | Назначение |
|------|-----|------------|
| `id` | INTEGER | идентификатор, первичный ключ |
| `purchase_id` | INTEGER | внешний ключ на `purchases.id` |
| `user_id` | INTEGER | внешний ключ на `users.id` |
| `is_cancelled` | INTEGER | признак отмены (0 — активно, 1 — отменено) |

Поле `id` каждой таблицы является первичным ключом (`PRIMARY KEY`). Поля
`participations.purchase_id` и `participations.user_id` — внешние ключи
(`FOREIGN KEY`), связывающие участие с конкретной покупкой и пользователем.

### Организация файлов базы данных
- `sql/schema.sql` — SQL-команды создания таблиц и ключей;
- `sql/queries.sql` — проверенные SQL-запросы проекта;
- `db/database.py` — подключение к SQLite (`get_connection()`,
  `PRAGMA foreign_keys = ON`);
- `db/import_json.py` — перенос данных из JSON-файлов в таблицы;
- `data/joint_purchases.sqlite` — файл базы данных.

### SQL-запросы
В файле `sql/queries.sql` хранятся запросы, реализующие задачи проекта:
выборка списков (`SELECT ... ORDER BY`), фильтрация (`WHERE`), соединение
таблиц (`JOIN`), агрегатные функции (`COUNT`, `MIN`, `AVG`, `MAX`),
группировка (`GROUP BY`) и фильтрация групп (`HAVING`), а также запрос с
подзапросом (`NOT IN`).

### Получение данных в Django
Django-представления получают данные из SQLite средствами модуля `sqlite3`:
соединение настраивается через `conn.row_factory = sqlite3.Row` (доступ к
полям результата по именам), результат запроса передаётся в шаблон через
контекст. Значения, полученные от пользователя (например, бюджет на странице
подбора), подставляются в запрос через параметры `?`, а не конкатенацией
строк.

## Хранение исходных данных
JSON-файлы каталога `data/` сохранены как исходные данные предметной области
и используются консольной версией приложения (`storage.py`, классы из каталога
`models/`). Django ORM и модели Django пока не используются — база данных на
этом этапе работает напрямую через SQL и модуль `sqlite3`.

## Создание базы данных
База данных уже находится в репозитории (`data/joint_purchases.sqlite`).
Чтобы создать её заново из JSON-файлов, выполните из корня проекта:

```
python -c "import sqlite3; sqlite3.connect('data/joint_purchases.sqlite').close()"
python -c "import sqlite3; c=sqlite3.connect('data/joint_purchases.sqlite'); c.executescript(open('sql/schema.sql', encoding='utf-8').read()); c.commit(); c.close()"
python -m db.import_json
```
